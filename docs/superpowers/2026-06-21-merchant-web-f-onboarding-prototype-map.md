## Backend contracts the frontend calls (merged B1-B5 on main)
- **B2** `GET /api/v1/merchant/onboarding/taxonomy` (top-level cats + RMV-eligible flag + full subcategories + per-subcategory cuisine/specialty tags) ; `POST /api/v1/merchant/onboarding/identity` (subcategory primaryCategoryId + cuisine primaryDescriptorTagId + MerchantTag specialties + MerchantCategory; draft-window gated).
- **B1** profile + branch sensitive fields write DIRECTLY in the draft window (status REGISTERED || onboardingStep NEEDS_CHANGES); else governed edit-request lane.
- **B3** `POST /api/v1/merchant/vouchers/rmv/create-flagship` (body `{ voucherType }`, eligible-only, creates ONE template-linked DRAFT RMV; cap = 2 via `FLAGSHIP_RMV_LIMIT_REACHED` 409; ineligible -> `VOUCHER_TYPE_NOT_ELIGIBLE` 400) ; RMV edit/submit via the B5.1 cores (`updateRmvVoucher` allowedFields = title/description/estimatedSaving/terms/imageUrl/merchantFields ; `submitRmvVoucher`).
- **B4** `setOpeningHours` SERVER-VALIDATED (single-period-per-day; `OPENING_HOURS_INVALID` 400) ; voucher `estimatedSaving` present+>0 (`SAVING_INVALID` 400, no hard floor) ; `GET /api/v1/merchant/onboarding/status` -> `{ status, comment, actionedAt }` (own merchant, empty when no row).
- **B5** `POST /api/v1/merchant/uploads/:kind` server-proxied image upload (logo/banner/photo; type/size/dimension validated; public URL).
- Checklist: `GET /api/v1/merchant/onboarding/checklist` -> `{ branch_created, contract_signed, rmv_configured (>=2), all_complete }`. Contract: `GET /onboarding/contract` + `POST /onboarding/contract/accept`. Submit: `POST /onboarding/submit`.

## Per-slice prototype contract (condensed)

- **F1 staircase hub:** 6 steps (1 Account=always done / 2 Category / 3 Profile / 4 Branch / 5 Vouchers / 6 Agreement). Gating: account->category->{branch,vouchers,agreement share ONE gate `downstreamUnlocked = categoryDone && profileDone`}. Step states: done/current/in-progress/locked/todo (client-derived; no persisted progress). Submit "Submit for review" enables only at `checklistDone===checklistTotal` (all 6) + a confirm-modal checkbox second gate. Lifecycle homes: setup(hub) / submitted / in_review / changes(hub+banner) / live / live_new / suspended(read-only+banner) / **rejected(DESIGN, mirror suspended)**. Status pill palette in the design-system note.
- **F2 category/identity:** primary tile (11, single) -> subcategory (single) -> cuisine (multi, FOOD-only [Restaurant/Takeaway/Pub & Gastropub], min 1) -> specialties (multi, optional) -> live descriptor `[cuisines, subcat].join(' ')`. Save -> `POST /onboarding/identity`. Gates the vouchers step. Change-category = confirm-guarded (resets flagship RMVs).
- **F3 profile (Tier-1):** logo(>=512sq,<=2MB) + cover(>=1600x600,<=5MB) image upload via B5; description (required, maxlength 600, live counter); website (optional); registered/trading-name mapping; company number; VAT Y/N + number. "Save and finish later" (partial) + "Save and continue". Sensitive fields write directly (B1 draft window).
- **F4 branch:** name (required) + description (optional, prefill) + address (postcode lookup) + branch phone/email/website + **opening hours (SINGLE-period-per-day, per-day open/closed, Open-24h=00:00->24:00, overnight accepted, omit-not-null for closed days) server-validated (B4 D8a)** + amenities (category-scoped chips) + branch banner (B5) + branch photos (up to 8, B5) + **4-digit redemption PIN**. Save-and-continue opens a confirm modal.
- **F5 voucher builder:** Step1 pick (5 eligible, BOGO recommended, TL+Reusable disabled-with-copy) + redemption-cycle primer. Step2 build (per-type fields + suggestion chips + terms Fair/Caution/Restrictive + "How this voucher stacks up" advisory score + auto-compose title<=60/desc<=300). Create via `POST /vouchers/rmv/create-flagship` then edit via `updateRmvVoucher` (merchantFields) + `submitRmvVoucher`. **Cap 2 (backend enforces).** **Submit NOT gated on score (CC-1).** ALL verbatim chip/term/scoring/compose logic is in the S0 extraction doc (`...-voucher-builder-extraction.md`) - confirmed accurate against the live prototype source. Scoring tiers Too weak/Good/Great with the exact thresholds in S0 §4.
- **F6 contract+submit:** key-terms card (6 bullets) + full-agreement modal (draft banner) + click-to-agree (checkbox + typed-name signature + read-only date; gate `agreeChecked && name`). Sign -> `POST /onboarding/contract/accept` (marks step done; does NOT auto-submit). Final submit is the F1 hub Submit. No version label on first sign; no Zoho. Owner-gate = owner-by-absence in M2 (explicit OWNER role-gate = M3).
